## 6. Requirements for an authenticated DK capture (not done; no credentials, cookies or tokens go in GitHub)
1. The owner signs in to DraftKings in the box browser (or their own device) in a legal state. The session lives only in the browser profile. Never export cookies, tokens or HAR files with auth headers to the repo, issues or artifacts.
2. For each event, record the event page URL with its numeric event ID, the server or page clock at capture, and the signed-in state, logged as "signed in yes/no" only.
3. Save per market: DK market ID, selection IDs, both sides' American prices, line, period and market type exactly as DK labels them, for spreads, totals, ML, team totals, halves, alternates and player props, with both Over and Under or Yes and No where offered.
4. Save the raw response bytes (JSON or HTML) to a box-local, gitignored directory. Commit only a manifest: URL, retrieval UTC, HTTP status and SHA-256 of the bytes, with headers stripped of cookies and authorization.
5. Capture before tip, with clocks in UTC (`Z`) and the CT tip shown separately. Re-capture within a set staleness window (the runner's quote-age gate) on game day.
6. Ingest through this module with provenance `DK_AUTHENTICATED_PROVIDER_CAPTURE`. Screenshot, PDF and CSV captures keep working, labelled unauthenticated.

Note: signed-out DK pages already give event IDs and start times (Section 2). Prices and market IDs need DK's sportscontent API, which is blocked from this box with HTTP 403 even before any sign-in.
