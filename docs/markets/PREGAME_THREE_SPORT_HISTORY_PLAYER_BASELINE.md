# Three-sport pregame player history baseline (PAPER / 0u)

This module removes *typed* player opportunity/rate/dispersion guesses from SportsEdge's independent research path. It is NOT a licensed data-provider ingestion system, sophisticated forecast, independent source attestation, market calibration, or approved betting engine.

`sportsedge/markets/pit_player_history_fit.py` accepts (1) a privately archived **normalized** per-player, per-game, per-stat box-score CSV, and (2) a separately archived exact event + roster/activity/source-clock context. The original upstream provider bytes and SHA should be preserved independently. The input file's own SHA is checked, and provenance from upstream is marked unverified.

## Archive input

Required exact nine columns, each stat line representing *one game and exact stable player ID*:

```
sport,game_id,game_end_utc,player_id,team_id,stat,opportunity_unit,opportunities,actual_stat
```

For NFL/CFB: PASS_YDS, COMPLETIONS, PASS_TDS, INTERCEPTIONS per PASS_ATT; RUSH_YDS/RUSH_TDS per RUSH_ATT; REC_YDS/RECEPTIONS/REC_TDS per TARGETS; other explicitly supported opportunity types require their own correctly documented denominator. For CBB: POINTS, REBOUNDS, ASSISTS, 3PM, STEALS, BLOCKS, TURNOVERS per MINUTES. Dataset must be generated by an authorized, deterministic provider-specific parser from **past final games only**; do not use bookmaker quotes, player names as identifiers, current/future same-game stats, or an as-of source downloaded after prediction.

Input context exact keys:

```json
{
  "schema": "sportsedge-prepregame-player-game-stats-v1",
  "sport": "NFL",
  "event_id": "GENUINE_EVENT_ID",
  "home_id": "GENUINE_HOME_ID",
  "away_id": "GENUINE_AWAY_ID",
  "event_start_utc": "<real pregame kickoff UTC>",
  "forecast_asof_utc": "<real freeze UTC>",
  "source_published_utc": "<real earlier source publication UTC>",
  "source_captured_utc": "<real earlier source capture UTC>",
  "normalized_history_sha256": "sha256:<digest of exact normalized CSV bytes>",
  "original_provider_sha256": "sha256:<digest of untouched original provider response>",
  "source_id": "NFLVERSE_WEEKLY",
  "frozen_roster": {"GENUINE_PLAYER_ID": "GENUINE_HOME_ID"},
  "confirmed_activity": {"GENUINE_PLAYER_ID": true}
}
```

Appropriate permitted source IDs are `CFB_DATA` (CFB), `CBB_HOOPR` (CBB), `NFLVERSE_WEEKLY` (NFL). These labels and their input hashes are **not themselves independently authenticated**. They are contracts for later evidence validation.

## Fixed, predeclared simple baseline — NOT an optimized edge model

For **every eligible player and stat**, never selected by the book market:
- Require at least four separately identified **earlier** games of that player/stat, using at most the last five by finish timestamp.
- Project opportunities = mean per-game previous opportunities.
- Project production-per-opportunity = sum(previous stat) / sum(previous opportunities).
- Project expected stat = their product (hence the previous-game mean). Empirical **sample** standard deviation from those earlier game stat values. Require strictly positive, finite SD.
- Block absent history, unconfirmed activity, changed team identity, missing denominators/zero variance or receiving/rushing opportunity below existing research guards. Keep exclusions visible in the census.
- No priors from gambling lines, no imputed player ID, no one-sided book anchors, no postgame repopulation, no fake distribution correlation. The 5/4 window is a transparent starter benchmark, **not a proven optimal parameter**.

This stage generates the exact `sportsedge-three-sport-player-opportunities-v1` file expected by the merged `player_projection_builder.py`, which then generates the existing `player_forecast_intake` CSV. A subsequent private `player_features_ref` can enter the full slate research model before screenshot prices.

Run with real archived data in a restricted private environment:

```sh
python -m sportsedge.markets.pit_player_history_fit \
 /private/league_history_rows.csv \
 /private/game_roster_context.json \
 /private/new_player_features.json \
 /private/new_history_fit_census.json
```

No existing history, rates, odds or predictions are overwritten; outputs are create-only. Tests use made-up player/game records:

```sh
python -m unittest sportsedge.markets.test_pit_player_history_fit -v
```

## Boundaries before "only screenshots produce wagers"

This baseline produces **conditional research-only player moments** when genuine immutable earlier-game rows and pregame active rosters already exist. Automated feed capture and normalization, exact real event and player roster identity, actual injury participation, new-game opportunities, team-score model source, bookmaker-original offer provenance, fit of calibrated conditional and joint distributions, untouched forward results, and issue #10 gates A-E remain prerequisites. Absent any verified ingredient, card emission stays PAPER/0u / BLOCK.

## Direct RUN IT input, without intermediate player-feature files

The existing event `projection_ref` research manifest may now include **exactly one** private `player_history_ref` instead of `player_features_ref` or `player_file`:

```json
"player_history_ref": {
  "history_path": "/private/previous_only_player_game_stats.csv",
  "history_sha256": "sha256:<real sha256 of normalized game stat bytes>",
  "context_path": "/private/game_and_roster_freeze.json",
  "context_sha256": "sha256:<real sha256 of event context bytes>",
  "odds_observed_at_utc": "<actual independent sportsbook observed UTC>"
}
```

It validates both original private files against their hashes, rejects changed/late, mismatched roster/event/team and model-cutoff context, and computes independent opportunities/rates/empirical SD in memory. The exact forecast CSV then passes unchanged through `player_forecast_intake.py` and the scenario/line pricer; the final report exposes `player_projection_producer: THREE_SPORT_PRIOR_GAME_HISTORY_UNCALIBRATED` and a complete nested `player_projection_builder_census.history_fit` with blocked status. This does not modify a historic bet, source or frozen v5.

The merged screenshot handoff accepts a frozen slate containing such `player_history_ref` event manifests. **That is a functioning research software pipeline from earlier-game player stat rows to fresh screenshot observations.** It still does not fetch/normalize real league feeds, prove that the point-in-time roster is authentic, fit a mature opponent-adjusted model, or certify wager probabilities. A pregame source worker must privately build and pin these files without user involvement before the last screenshot arrives. No model source or official betting gate can be substituted by a screenshot.

End-to-end synthetic regression:
`python -m unittest sportsedge.markets.test_player_history_run_it -v`.
